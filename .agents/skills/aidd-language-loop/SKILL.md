# 言語ごとの TDD ループと品質ゲートを立ち上げる

## いつ使うか

- 案件リポで最初の外側テストを書く前、言語が追加されたとき
- 道具の選定で止まったとき、品質ゲートが複数コマンドに散らばっているとき

## 先に読むもの

1. 案件リポの `AGENTS.md`（1 コマンドと道具が書いてあればそれに従う）
2. [PB-00023](../../../playbook/00023-set-up-language-tdd-loop.md) — 手順の正本（言語別の既定候補）
3. [ADR-00026](../../../adr/00026-fix-loop-shape-let-projects-pick-toolchains.md) — 固定するもの / 案件が選ぶもの
4. [PB-00013](../../../playbook/00013-start-tdd-from-examples.md) — ループの回し方

## 手順の要点

1. 品質ゲートを「整形検査 → 静的検査 → 単体 → 外側」の 1 コマンドにし、PR 単位の CI で回す
2. 外側テストを内側と分けて走らせ、各外側テストに受け入れ例の行を書く
3. 道具は既定候補（表）から採り、変えるなら案件 ADR に理由。導入は `build:` / `ci:` コミットに分ける
4. 案件 `AGENTS.md` に 1 コマンド・外側だけのコマンド・道具を書く

## 禁止事項

- 品質ゲートの 4 段のどれかを省く。落ちるゲートを緩めて通す
- 外側テストを内部構造に依存させる
- 道具の導入と振る舞いの変更を同じコミットに入れる
- 手順の詳細をこのファイルに書き写す（正本は PB-00023）
