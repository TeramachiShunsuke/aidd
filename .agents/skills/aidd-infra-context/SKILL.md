# インフラ文脈の受け渡し

## いつ使うか

- エージェントに DB / インフラ作業をさせる前
- 既存の構成ドキュメントが古くて信用できないとき

## 先に読むもの

1. [AGENTS.md](../../../AGENTS.md)
2. [PB-014](../../../playbook/014-hand-infra-context.md) — 手順の正本
3. [ADR-014](../../../adr/014-infra-context-layers.md) — 3 層の分け方

## 手順の要点

1. 情報を制約 / 契約 / 状態に仕分ける
2. 制約は KB の ADR から読ませる。なければ先に書く
3. 契約は定義ファイルを直接読ませる。要約を作らない
4. 状態は取得コマンドを実行させる。可逆な変更は試して測り、結果を evidence にする

## 禁止事項

- 現在の構成・パラメータ実値・データ量を Markdown に書く
- 手で維持する構成図や環境一覧を作る
- 取得できなかった状態を推測で埋める（open-questions に残す）
- 不可逆な変更（テーブル分割、シャーディングキー）を ADR なしで進める
