# 実装スペックの振り分け

## いつ使うか

- 実装スペックを書き始める前、または既存の設計書が維持できなくなったとき
- 「この設計は文書に残すべきか」で判断が止まったとき

## 先に読むもの

1. [AGENTS.md](../../../AGENTS.md)
2. [PB-012](../../../playbook/012-triage-implementation-spec.md) — 手順の正本
3. [ADR-014](../../../adr/014-implementation-spec-split.md) — 判断基準

## 手順の要点

1. 対象を箇条書きにし、各行を契約 / 決定 / 振る舞いに判定する
2. 振る舞いは消してテストにする。契約は機械可読な定義に置き換える
3. 決定は「共有境界・不可逆・選択肢あり」のどれかを満たすものだけ残す
4. 横断する決定は KB の ADR、案件限りは spec リポジトリ側に置く

## 禁止事項

- 入出力の対応（振る舞い）を文書に書き写す
- DDL や JSON スキーマの本文を設計書に貼る
- 条件を満たさない決定を「念のため」書く
- 案件固有の詳細を KB に持ち込む
