# ライフサイクル矛盾の解消と、自己レビューで見つけた運用上の穴

- 期間: 2026-08-09 — 2026-08-09
- 範囲: `main`（commit `ec2a39c`）と、未着地のブランチ 2 本。観点は「規約どおりに運用し続けられるか」

## 2026-08-09

### 実施者

- 本リポジトリのエージェント（Cursor）による自己レビュー。[REV-005](005-adversarial-review.md) が挙げた P0 のうち、期限のあるものから着手した

### 結果

**確認した文書**: frozen 5 件（ADR-001 / 002 / 003 / 005 / EVID-004）を全文読み直し、[ledger/attestations.md](../ledger/attestations.md) に証跡を残した。ADR-004 / PB-003 / PB-004 / PB-005 と規範 3 点（AGENTS / CONVENTIONS / README / GUIDE）を検査の変更に合わせて読み直した。

**更新した文書**: [ADR-012](../adr/012-review-attestations.md) を新規作成し、`check-staleness.sh` を書き換えた。詳細は changelog を参照。

**機械的に確かめたこと**（すべて `check-staleness.sh` の実行結果）:

- `MAX_AGE_DAYS=0` で走らせると、証跡のある frozen 5 件は通り、証跡のない ADR-004 だけが落ちる。証跡が実効レビュー日を延ばしていることの確認
- `TODAY=2026-08-01` で 40 件が「未来日」で落ちる。前借りが塞がっている確認
- 実在しない ID を指す証跡と、未来日の証跡がそれぞれ専用エラーで落ちる
- 期限は EVID-016 の記載どおり 2026-11-07（`TODAY` を 11-06 / 11-07 / 11-08 と動かして確認。11-06 は 0 件、11-07 から期限切れが出る）
- スクリプトから GNU 依存（`date -d` / `mapfile`）が消えた。日付演算は awk の civil-days 実装に置き換えた

### 自己レビューで見つけた穴

1. **設計した仕組みが 2 本、main に届いていなかった**。PR #7（検査の等級分け）と PR #9（実装スペックの分割 / TDD / インフラ文脈）は「マージ済み」だが、マージ先は積み上げたブランチであって `main` ではない。積み上げ PR の親をマージした時点で子も入ったと錯覚したのが原因。しかもその間に PR #8 が入り、EVID-016・ADR-012・OQ-013..016 の**番号が衝突**している。着地させるには採番のやり直しが要る
2. **番号の衝突は仕組みで防げていない**。`build-index.sh` は `id` の重複を検出するが、それは同じブランチに両方が存在するときだけ。別ブランチで同じ番号を使い始めたことは、マージするまで誰も気づけない
3. **鮮度が一斉に切れる**。全文書の `last_reviewed` が 2026-08-08 か 08-09 に集中しているため、期限も 2026-11-07 と 11-08 の 2 日に集中する。週次 `schedule` を入れた結果、その週に main が 40 件超のエラーで赤くなる。証跡を分散して入れれば緩和できるが、緩和策は運用側にあり仕組みにはない（OQ-018）
4. **AGENTS.md の完了条件が「次の 2 つ」と書いて 3 つ並べていた**。この PR で直した。生成物と違い、規範の本文は誰も検査していない
5. **同じ表が 3 か所にある**。Tier の表は README / CONVENTIONS / GUIDE に、ツール対応表は AGENTS / README / GUIDE にある。今のところ内容は一致しているが、[EVID-010](../evidence/010-handwritten-index-rots.md) が索引について言ったことは、この種の手書きの表にもそのまま当てはまる（OQ-019）
