# PF クライアント表面（IDE 拡張 → アプリ / Web / CLI）構想に対する敵対レビュー

- 期間: 2026-08-14 — 2026-08-14
- 範囲: commit `2f08e23` の知識ベース全体。前提は「PF を VS Code / IntelliJ などの IDE 拡張として始め、ゆくゆくクライアントアプリまたは Web アプリへ広げ、CLI も選択肢に入れる」
- 実施者: 同一セッションのエージェント。REV-007（主体・認可・実行状態）の上に、**配信面（surface）と着手順**だけを敵対的に見る

## きっかけ

[ADR-020](../adr/020-platform-is-a-client.md) は「PF はクライアント」「本リポジトリに PF を実装しない」「正本は git の Markdown + PR」を既に固定している。運用者は次に、そのクライアントの**形**として IDE 拡張を第一世代に置き、後からデスクトップ / Web、任意で CLI を足す流れを示した。認可と正本の話は REV-007 で閉じた／残したまま、表面の選択そのものが ADR-020 と衝突しないかを再監査する。

## 指摘と再検証の結果

## 用語（本レビュー内）

| 語 | 意味 | 意味しない |
| --- | --- | --- |
| surface | PF の操作面（IDE 拡張 / CLI / Web / desktop） | 案件の画面デザイン（Figma。OQ-028） |
| クライアント契約 | git を読み、下書きを提案し、PR まで出す。第二の文書ストアを持たない | 拡張固有の設定 UI |
| エージェント経路 | AGENTS.md / skills / playbook をエージェントが直接読む経路 | PF のサイドバー操作 |

## 対応方針

1. **今は表面を実装しない**（ADR-020 §1 を維持）。本レビューは批判と未決の切り出しまで
2. **表面より先にクライアント契約を 1 つに固定する候補を検討する**（OQ-037）。IDE / CLI / Web は薄い皮。状態機械・文書正本・認証情報は皮に置かない
3. **kernel に IDE / 製品チャネル名を焼き付けない**（EVID-029）。特定拡張の手順は実装リポ側
4. **着手順の仮説を逆さに検証する**: IdP・ACL・コネクタが本命なら Web（または認証を持つ薄いホスト）が第一世代候補。エージェントと人間が同じ操作を共有するなら CLI が第一世代候補。IDE 拡張は「エディタ内の摩擦を減らす便利面」であり、認可 PF の本体にはなりにくい
5. **VS Code と IntelliJ の同時第一世代は採らない**前提で議論する（OQ-036）。1 表面で学び、橋は後から
6. **着工条件は REV-007 を継承**: OQ-017 / OQ-032 / OQ-033 / OQ-034 が空のまま複数 surface を増やさない。本レビューで OQ-035..037 を追加

## 未対応の判断

- 第一世代 surface の決定は人間（OQ-035）。本レビューは「IDE 拡張同時スタート」に反対し、代替順序を示すに留める
- ADR-020 の改訂は不要。表面の順序は後継 ADR か、実装リポの ADR で足りる
- CLAIM の追加は、表面順序を決めたあとにする（今は仮説）

## 判定（要約）

構想の「PF はクライアントで、後から形を増やせる」方向は ADR-020 と両立する。敵対する点は**形の増やし方**である。VS Code + IntelliJ を第一世代にし、認証と ACL を後回しの Web に先送りする順序は、未決の難題と実装コストの両方を最悪に寄せる。先に共有クライアント契約を置き、第一世代は 1 表面に絞れ。その 1 つが IDE 拡張である必然は、現状の KB だけでは示せていない。
